# 虚构来源：超时后停止

以下是从零编写的练习资料，不对应任何个人、公司、真实程序或实际工具输出。日期只用于展示证据先后关系。

## 资料 A：初始记录，2025-01-10

### 参与者自述

> 我给一个 Python 练习脚本实现了重试和最终停止。脚本遇到超时后会再试一次。这样应该让性能提升了 30%，但我没有做对比测量。

这段话当时只有参与者自述，没有代码修改记录，不能据此确认“重试机制也是自己实现的”。“性能提升 30%”没有测量依据。

### 行为记录

以下是预写的虚构测试记录，不是此仓库运行测试的结果：

```text
initial attempt: timeout
retry attempt: timeout
next action: stop
underlying timeout cause: unresolved
```

记录只描述本次练习中的行为，不能证明吞吐量、延迟或成功率改善。

### 技术范围

参与者使用 Python 修改脚本并编写相关测试。这个练习没有使用 Kubernetes，也没有生产部署记录。

## 资料 B：补充记录，2025-01-11

练习追问后，参与者提供了下面的虚构修改核对记录，并确认初始自述的职责范围不准确：

> 修改之前，脚本已经会在首次超时后重试一次。这段重试机制来自已有代码，不是我实现的。我的修改是在重试仍超时后加入明确的停止条件，并补充测试，确认不再发起后续尝试。最初“实现了重试和停止”的说法把已有代码算进了自己的贡献，需要修订。

修改核对记录：

| 对照项 | 修改之前 | 参与者的修改 |
| --- | --- | --- |
| 首次超时后重试一次 | 已有 | 没有实现或改写这段机制 |
| 重试仍超时后停止 | 缺少明确条件 | 补充停止条件 |
| 停止行为相关测试 | 未包含本例断言 | 增加首次与重试均超时后停止、不再发起后续尝试的断言 |
| 性能测量 | 没有 | 没有新增测量 |

补充资料解决了职责归属冲突；它没有解决超时根因，也没有给“性能提升 30%”增加依据。
