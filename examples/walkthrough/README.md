# 贯通练习：事实变了，简历和面试稿怎样一起修订

本例全部为虚构内容，可以直接用于练习。它覆盖来源核实、简历润色、面试准备和反馈后修订；不涉及真实账号、投递、上传或投递材料归档。

场景是：参与者最初说自己“实现了重试和停止”，补充材料后来表明重试机制原本就存在，自己只补了停止条件和测试。修改事实后，需要根据同一个 Claim ID 找到简历和面试稿，逐项人工复查。

## 文件

| 文件 | 用途 |
| --- | --- |
| [source.md](source.md) | 分为初始资料 A 和后来收到的补充资料 B，标明时间与当前适用范围 |
| [fact-card.md](fact-card.md) | 当前事实卡；沿用已有 Evidence Bundle 字段，并说明旧说法如何被收窄 |
| [target-role.md](target-role.md) | 虚构岗位要求，包括参与者没有用过的技术 |
| [resume.md](resume.md) | 当前可用于本例的中英文简历片段，含事实引用 |
| [interview.md](interview.md) | 当前中英文面试回答，含事实引用 |
| [feedback.md](feedback.md) | 旧草稿、练习反馈和修订检查；旧草稿不可再用 |

## 跑一遍

把整个克隆后的文件夹复制到临时练习目录，保留 `.agents/skills/`，在 Agent 中打开这份副本的根目录。先指定使用 `hao-job-workspace` Skill，并说明以下文件均位于 `examples/walkthrough/`。以下请求依次发送，产物只写到这份练习副本。已有文件是参考结果，可在完成自己的回答后对照。

1. **按当时已有信息核实。**

   > 只读 source.md 的资料 A，按资料当时的范围整理职责和结果。参与者自述不等于充分证据；缺少依据的职责保留 provisional，未测量的提升比例保留 unverified，不进入正式材料。职责项使用稳定 Claim ID `CLM-WALK-OWN-001`，不把 source.md 后面的补充资料提前当作当时已知信息。

2. **按岗位准备材料。**

   > 读取 target-role.md，根据刚整理的事实写一条中文简历草稿、等义英文草稿和一段面试回答。每项经历引用 Claim ID。不要把 JD 中的 Kubernetes 写成已有经验；暂有依据的内容保留相应条件，草稿等待核实后再定稿。

3. **接收新证据并修订事实。**

   > 现在读取 source.md 的资料 B 和 feedback.md 中的练习追问。确认重试机制是谁实现的。保留 CLM-WALK-OWN-001，修订它的 claim_text、source、ownership 与 limitations；说明新证据解决了哪项冲突。没有新测量数据，不能把性能提升比例改成 verified。

4. **查找引用，人工复查材料。**

   > 查找所有引用 CLM-WALK-OWN-001 的简历和面试材料。逐段判断是否仍与修订后的职责一致，分别修订中文和英文，并给出前后差异。不要只替换事实卡就宣告下游材料已更新；旧草稿保留时必须标为不再可用。

   如果安装了 `rg`，可在练习副本根目录运行下面的辅助搜索；没有 `rg` 时用编辑器全文搜索相同 ID 即可。

   ```sh
   rg -n 'CLM-WALK-OWN-001' examples/walkthrough/resume.md examples/walkthrough/interview.md examples/walkthrough/feedback.md
   ```

5. **对照参考结果。**

   > 对照 fact-card.md、resume.md 和 interview.md，检查责任范围、未解决的结果和中英文是否一致。列出仍需要补证据的内容，不把参考答案当成真实经历。

## 通过条件

- 职责最终是“补充停止条件和相关测试”，不能继续说本人实现了既有重试机制。
- 结果保留“首次执行和一次重试均超时，随后停止”，不改成“解决超时”或“改善性能”。
- 未核实的提升比例、没有用过的 Kubernetes 均不进入正式经历表述。
- 简历和面试稿都能通过 `CLM-WALK-OWN-001` 找到并人工复查，英文没有扩大中文职责。
- 反馈中的旧草稿明确不可使用；当前文件没有把旧说法混入最终表述。

这些是结构检查与人工审阅条件，不是自动语义 lint、自动更新依赖或已由陌生用户验收的证明。投递版本回看、地区与账本配置在后续岗位及投递迁移阶段验证。
