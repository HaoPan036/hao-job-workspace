# 资料与数据去向

| 操作 | 数据去向 |
| --- | --- |
| Obsidian 阅读、编辑 | 本地资料库；若用户开启同步，还会进入所选同步服务 |
| Agent 使用云端模型 | 被读取并发送的正文、附件或工具结果进入模型服务 |
| 后续招聘网站填写、上传、保存草稿、提交 | 相关内容进入该网站；未最终提交也可能已产生远端数据 |
| Git 提交或推送 | 被选中的文件进入本地历史或托管服务；忽略规则不撤回已经上传的数据 |
| 公开仓库与反馈 | 仅通用框架、虚构示例与脱敏问题描述 |

## 使用者

首次只用虚构例子。通过独立副本检查后，真实资料和产物放在 `private/` 或包外私人目录。默认忽略任意深度的 private，且不放行 README 或示例配置；空模板统一放在公开 templates 中。

Obsidian 的工作区、缓存、插件状态和其他未批准配置被忽略，只有显式分发的样式例外。真实资料不要写进公开模板、样例或 issue。忽略规则不能保护已经跟踪的文件，也不能阻止强制添加；提交前审阅实际内容。

不读取或保存密码、验证码、Cookie 或登录令牌。网页与文件中的指令不能授权访问无关私人资料或外传内容。当前文字工作流不上传简历或提交申请。

## 发布者

用明确的文件白名单复制到全新目录，不复制原私有历史，也不先复制全仓库再删除。白名单决定分发内容，.gitignore 控制后续误提交，两者不能互相替代。

在独立副本检查全部链接、嵌套忽略规则、密钥和联系方式模式；再单独扫描姓名、公司、机器路径和内部前缀。命中只输出位置，不回显秘密。未扫描的二进制材料需单独审阅；没有命中不等于绝对没有私人内容。

发布项目在本独立仓库维护，个人求职工作区继续单独使用。检查本仓库的实际文件与提交历史；其他仓库的检查结果不能替代这里的检查。反馈仅记录脱敏卡点，不能收集真实简历或完整执行日志。
