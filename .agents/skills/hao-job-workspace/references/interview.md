# 面试准备、复盘与陪练

按用户要的交付物选择下面一个入口，不默认把三阶段全部运行。个人经历遵守 [事实规则](evidence.md)；通用概念题无需读取个人经历或创建 Evidence Bundle。

## 写作与岗位准备

从指定问题、已有稿、相关事实和 JD 开始。公司、岗位、轮次分别确认，不能从相邻文件或另一 AI 的标题推断。缺少某轮资料时可以准备明确标注为通用的内容，不能假装掌握真实面试安排。

项目和行为题用 STAR 自然叙述：背景任务简短，重点写自己的行动与实际结果。正文不逐段喊出框架名称，不为了凑 Result 编造数字。概念题先直接回答，再用具体例子解释，不硬套经历故事。

只为当前答案核查新的数字、职责、机制和使用范围；既有且范围匹配的事实直接复用。把有影响的条件自然写进答案，事实 ID 和核验过程另列引用说明。

岗位准备优先覆盖已知轮次、JD 和用户已有反馈，补相关追问与可问面试官的问题。需要公司最新业务、产品或岗位信息时核对官方资料并给出来源；无法访问时明确缺口，不捏造背景。

若问题依赖“你当时投递的简历”，先按用户给出的公司、岗位和材料记录 ID，沿 [记录与归档](records.md) 找到该申请记录及其引用的原版本；没有记录时请用户提供该次材料，仍缺失则明确未知。当前修订稿不等于历史提交稿，旧准备稿也不证明提交过。未知历史版本不阻塞独立的技术准备；面试准备本身不建立或回填成功记录。

中英文稿按用户要求交付，保留相同事实范围，分别组织成自然表达。不要把新的推荐定位写成用户已经确认的职业选择。

需要成套准备时使用 [准备模板](../../../../templates/interview/preparation.md)，按当前轮次选取问题，不要求每次填满所有章节。技术题可按需读取 [面试主题清单](interview-topic-checklist.md)，只选择相关主题；它是选题提示，不是标准答案、能力证明或完整学习计划。已有完整答案优先使用用户提供的当前来源，不新建重复题库。

## 已有回答复盘

- 读取实际问题与回答，区分真实面试、练习和另一 AI 的建议。保留原始逐字稿及用户原话。
- 对每个实质问题给出“问题在哪 → 正确做法与回答”。在当前文档中直接解释并给出修正答案，不能只丢一个链接或把纠错藏在折叠里。
- 区分事实错误、解释不全、术语不准和表达偏好。缺失的转录不是答错，不把口语夸大成用户没有说过的绝对承诺再批评。
- 保留正确部分，不强行为每题找错；未做过的测试写成建议步骤，不写成既有结果。引用和原文位置可另列。
- 用户要求“复盘并准备下一轮”时，将有用纠错带入写作即可，不重做整轮审计，不自动改事实主文或记录掌握程度。

保存复盘时可用 [复盘模板](../../../../templates/interview/review.md)。保留本轮原始回答与当时的纠错；只有用户另外要求更新长期答案时，才修改其现有答案主文。

## 互动练习

模拟面试或随机题一次给一个聚焦问题，等待用户回答；明确要求题单或批量练习时按其要求。用户尝试之前不提前给参考答案。

根据实际回答追问。反馈指出答得好的部分和最值得改善的一处，再给具体解释、自然的修正答案或针对性重试。用户说不理解时先用实例讲清楚，再继续练习。

只有用户要求保存练习记录时，才保存真实尝试、反馈和下一步。参考答案与用户回答分别标识；给出参考答案不等于用户已经掌握，不创建虚构成绩。

已要求保存的练习使用 [陪练记录模板](../../../../templates/interview/practice.md)。下一次根据本次实际暴露的问题追问，不把参考答案或题目清单登记成完成记录。岗位准备、复盘和继续追问的完整虚构示例见 [面试练习示例](../../../../examples/walkthrough/interview-cycle.md)。

## 保存与复查

使用用户指定的路径或其现有资料索引，不另建固定公司、地区或题库目录。仅要求口头回答、审阅或陪练时不写文件；已要求保存成稿或复盘时保存指定产物，不改写原始记录。

个人经历稿按事实 ID 另列来源引用。事实更新后的查找与人工复查遵守 [复查方法](evidence.md#事实修改后的复查)，不宣称自动同步了所有面试答案。
