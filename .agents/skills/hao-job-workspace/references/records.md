# 记录、统计与实际投递版本

岗位被找到、排队、准备好材料、填完、通过审查或点击 Submit 都不是成功。仅凭已授权提交后的官方成功依据，或用户对该具体申请的明确成功确认，更新成功记录。

仓库工具的 Python 代码检查结构、路径、哈希、重复和计数；它们不访问招聘网站，也不能鉴别传入的成功证据是否真实。Agent 必须先核对原始结果，不能为了通过工具而构造 `success_proven`。

## 更新记录与统计

先读 `tools/recruiting-sync/README.md`，按 `templates/recruiting/` 初始化本地配置、历史和待办到 `private/recruiting/`。地区、实习/全职类别、路径与 Markdown 表头来自使用者自己的配置，不套用维护者地区。

1. 用本次实际结果填写原有 `application_execution` 事件。真实事件、计划和台账必须 ignored + untracked；示例只用于演示。
2. 运行 `plan` 生成局部补丁、输入快照和统计结果；运行 `check` 立即核对快照，再用 `apply_patch` 应用补丁，接着 `verify`。按工具 README 的实际命令，不跳过输入版本检查。
3. 历史与待办成对核对，实习与全职分开计数，同一岗位的重复成功不增加数量。`audit --json` 只读返回当前分类 `counts`、`history_rows` 和 `issues`；有问题时说明缺口，不能把部分计数报告为完整统计。不是用简历文件数或点击次数充当投递数。
4. 文件在计划后变化时重新核对并规划；不能覆盖别人新改的记录。多文件补丁不是跨文件事务，部分失败时检查哪些已生效，再修复剩余本地记录，禁止重新向网站提交。
5. `verify` 通过后，从用户指定资料索引或已配置的 job-search profile 解析 `current_actions`、`dashboard`，相对路径以 profile 所在目录为基准。移除该岗位已经完成的“申请/提交”行动，只改已过期摘要；保留用户其他任务和优先级，不添加未经要求的跟进或备考任务。工具的 `review_locations` 只覆盖历史与待办，不能代替这一步。用户未配置行动页时直接报告无此页面，不创建第二套入口；已配置页面缺失则报告待修复，不能声称行动页已同步。
6. 重读本次修改的历史、待办与行动页，确认不再同时出现“已提交”和该次待投任务，再报告本地记录完成。测评、面试、拒绝或 Offer 等后续变化按 [运营规则](operations.md)更新既有行，不再生成一条提交事件。

## 归档实际材料

读取 `tools/application-record/README.md`，把实际批准且已上传的文件路径、版本、预期 SHA-256、岗位和成功证据放入 ignored 的输入 JSON。先 `--validate-only`，再执行归档。工具将原字节保存到 `private/application-records/objects/`，每份申请记录引用其哈希；同 ID 的内容不得悄悄覆盖。

只归档普通项目回答和必要申请信息，不记录密码、验证码、证件号、Cookie 或敏感声明全文。文件仍需存在并与上传时哈希一致；丢失时报告无法归档，不用后来改过的简历冒充。

## 找回当时的简历与回答

1. 在用户指定的申请历史中按公司、岗位 ID / 准确官方 URL 和批次定位唯一申请，读取备注中的材料记录 ID。只有公司或相同岗位名而出现多次申请时，先厘清是哪一次，不取最新一条代替。
2. 读取该工作区 `private/application-records/records/<record_id>.json`，再核对其中 `application` 的岗位、申请编号和已知日期。这个 JSON 是归档记录，不把准备时的输入文件当作成功归档证明。
3. `resume.object_path` 相对于 `private/application-records/`，正常为 `objects/<sha256>.pdf`。只读取所选记录引用的对象，核对其字节 SHA-256 与 `resume.sha256` 一致；从 `resume` 取得方向、语言、版本，从 `form_answers` 取得当次实际普通回答。无需扫描其他材料目录，也不需要新建检索数据库。
4. 向用户给出原版本的可打开文件链接和版本说明。材料记录或对象缺失、哈希不符时报告该具体缺口；不要取当前简历填补。缺少历史材料时可用用户当前可核实资料继续准备，但明确它不是当时版本。

归档工具只保存字节，没有搜索或 PDF 解析命令；上面由 Agent 按明确记录路径读取。需要读取 PDF 正文时使用已验证且获准的文档工具。旧提交材料只证明当时写过什么，不替代个人经历的事实依据。

官网成功而同步/归档失败时，分别报告“提交已成功”“记录/归档待修复”。保留证据，修复本地阶段即可。不要为了让所有状态看起来一致而撤销已证实的成功或重复提交。
