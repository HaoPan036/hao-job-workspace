# 第一次使用：建立自己的资料

用户说“初始化”“第一次用”“帮我建资料”或运行 `/setup` 时使用。目标是在被 Git 忽略的 `private/` 里，把用户已有的资料整理成后续环节能直接用的档案，并列出还需要用户确认的问题。初始化不找岗位、不投递、不联网、不读邮箱。

## 1. 先建空档案，确认私人资料不会进 Git

在仓库根目录依次运行，并把关键输出告诉用户：

```sh
python3 tools/workspace/setup.py init
python3 tools/workspace/setup.py check
git check-ignore -v private/material-index.md
```

`init` 只补缺失模板，已有文件保持不动。最后一条命令没有输出时停下：说明 `private/` 未被忽略，按 [初始化说明](../../../../tools/workspace/README.md#确认-private-被忽略) 处理，处理好之前只用虚构资料。只装了 Skill、没有仓库工具时，跳过这一步，改为询问用户资料放在哪里、输出写到哪里。

## 2. 选一条路开始

已有内容时直接用，不重复提问：

| 情况 | 做法 |
|---|---|
| `private/inbox/` 里已有文件，或用户给了文件路径 | **读资料**：简历、项目笔记、LinkedIn 导出、过往申请材料 |
| 用户在对话里贴了一份简历或经历 | **读粘贴内容** |
| 什么都没有 | **问答**：一次问一组，见第 4 节 |

请用户把资料**复制**到 `private/inbox/`，不移动、不覆盖原件。Markdown 和纯文本最稳；PDF、Word 能否读取取决于宿主，读不出或读出乱码时请用户另存为文本，不要猜内容。

## 3. 写进哪些文件

全部写在 `private/` 内。已有记录先读再补，不覆盖用户填过的内容；要改已有内容时，先给出修改前后的差异。

| 内容 | 位置 | 怎么写 |
|---|---|---|
| 资料清单 | `material-index.md` | 登记每份来源的路径、当前简历及语言，输出目录默认 `outputs/` |
| 项目和经历的事实卡 | `facts/<简短英文名>.md` | 每项可单独核实的职责、实现、使用、结果各一条，按 [事实规则](evidence.md) 的十个字段，`claim_id` 用可读的唯一 ID |
| 教育与工作经历 | `application-profile/facts.json` | `education`、`employment` 条目，`status` 写 `NEEDS_CONFIRMATION`，`source` 写来源文件 |
| 求职方向 | `job-search/profile.json` | `target_roles`、`locations`、`feasibility.work_authorization_by_location`、`allowed_graduation_years`；`application_queue.enabled` 保持 `false` |
| 投递记录的地区分类 | `recruiting/config.json` | 模板里的 Singapore / Canada 只是示例；用户给出自己的地区后再改，没给就不动 |

事实状态按来源定，不因为“写进档案”就升级：

- 简历、旧申请材料和准备稿只是线索，抽出来的说法一律先记 `unverified`，`source` 指向原文位置。
- 用户在本次对话里明确确认的职责和使用范围，可以改为 `verified`，`source` 写“用户确认”和日期，`scope` 只写确认到的范围。
- 结果和数字缺少口径（基线、样本、时间、测量来源）时保持 `unverified`，不补数字。
- 求职偏好、工作许可这类信息按用户原话记录；没说的留空，不推断国籍、签证或毕业年份。

## 4. 问答：一次一组，可以跳过

1. 求职方向：想找的岗位、全职还是实习、地区，以及不能接受的条件。
2. 身份与时间：各地区的工作许可（例如是否需要签证担保）、毕业时间、最早入职时间。
3. 教育：学校、学位、专业、起止时间。
4. 经历：每段工作或实习的公司、职位、时间，以及你自己负责的事。
5. 项目：挑两三个最想写进简历的，各说清楚做了什么、哪些是你写的、有没有结果数据。

用户说“跳过”就留空。资料里已经有的内容不再问，只问冲突和缺口。

## 5. 收尾

再运行一次 `python3 tools/workspace/setup.py check`，然后告诉用户：

- 新建或补充了哪些文件，各写了多少条；
- **待确认清单**：最多十条，每条一句问题，优先列会进简历的职责和数字，以及来源之间的冲突；
- 下一步可以做什么，例如“针对一个岗位改简历”或“按我的条件找几个岗位”。

不要把空模板通过检查说成资料齐全，也不要把档案里的 `review_then_submit` 当成投递授权。
