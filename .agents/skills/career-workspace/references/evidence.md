# 事实与引用

## 什么时候核验

从具体疑点开始：用户要求核实、新增或改变的事实没有依据、现有来源直接冲突。已经成立且范围匹配的事实可以复用；改措辞、顺序或术语不自动触发全项目审计。

把复合表述拆成有疑点的部分即可。代码可支持实现行为，不能单独证明个人职责、团队采用或业务成效。明确的用户确认可以支持其亲历范围内的职责与使用情况；注明确认内容及日期，未知日期不编造。

## 沿用的 Evidence Bundle

事实卡使用以下十个既有字段，不新增发布版本、自动依赖关系或审核字段。已有 ID 保持稳定；新卡使用资料库内唯一的可读 ID，不强制特定前缀。

```yaml
evidence_bundle:
  claim_id: ""
  claim_text: ""
  claim_type: implementation
  evidence_status: unverified
  source: []
  scope: ""
  date: unknown
  ownership: ""
  allowed_use: []
  limitations: []
```

- `claim_text`：已支持的可复用事实；若仍未核实，保留原命题作为待检查的问题，不能传成事实。
- `source`：可定位的笔记段落、代码或测试位置、实验记录、提交或明确用户确认。文件存在本身不证明作者、上线、使用或结果。
- `scope`、`ownership`：成立范围与个人实际职责，不能把团队产出自动归于本人。
- `date`：来源记录或核验的日期，必要时在文字中区分；未知为 `unknown`。
- `allowed_use`：用户允许的使用场景；空值不是任意使用的许可。来源公开也不等于用户允许把个人经历公开。
- `limitations`：会改变结论的条件、缺口和保密限制。

`claim_type` 可取：`implementation`（实现）、`ownership`（职责）、`usage`（使用）、`outcome`（结果）、`metric`（指标）、`plan`（未来计划）。

| `evidence_status` | 使用规则 |
|---|---|
| `verified` | 在该事实的范围与 `allowed_use` 内使用，不能扩大结论 |
| `provisional` | 部分支持；仅使用成立的部分，保留影响结论的条件和限制，不写成无条件事实 |
| `planned` | 只用于明确的未来计划；不能进入简历的已完成经历或冒充过去的面试事例 |
| `retired` | 已撤回；不静默恢复或从旧稿重新带回 |
| `unverified` | 不进入正式简历和面试答案；只可作为待核实问题记录 |

指标必须有数值定义、分母、样本、时间窗口和测量来源，写入适当的既有字段中。若某项不适用，说明理由。缺少关键口径时不使用容易误导的数字，仍可交付支持充分的定性结果；绝不为凑结果编造百分比。

这些是 Agent 的工作规则，字段完整不证明事实真实，也不代表程序已经验证正文与来源的语义一致。

## 来源冲突

1. 实现行为使用当前可检查的代码、测试、评估或明确版本；职责、采用、结果和保密范围使用明确用户确认或权威记录。
2. 当前事实主文记录既有对外表述边界；旧简历、准备稿和历史记录只是线索，不能自动覆盖当前事实。
3. 冲突未解决时，暂停对外使用有争议的命题，在工作记录标明 `reconciliation_required`，按依据保留为 `unverified` 或带限制的 `provisional`。这只是工作记录说明，不新增 schema 字段。
4. 无争议的较窄事实可独立表述。不要选“更好听”的版本，也不因一个数字未知而阻塞所有已支持内容。

核验默认只读。用户授权更正事实源时，保存更正依据和仍存在的限制；单纯润色或演练不会提升证据状态。

## 事实修改后的复查

每份生成材料附独立引用说明：材料的章节或条目、对应 `claim_id`、事实卡位置和必要条件。可在稿末独立列出或保存为用户指定的伴随笔记；导出朗读稿时不把引用读进正文。

用户要求更正事实并复查材料时：

1. 先在授权范围内核实并更正事实主文，保留来源和原始记录。
2. 在用户指定的材料目录检索该 ID 与事实卡引用，列出匹配的简历和面试稿及位置。没有引用的旧材料可能漏检，不宣称结果完整。
3. 人工检查每个匹配项是否受到影响；正文和中英文版本都要检查，引用命中本身不等于内容错误。
4. 只修改已授权的材料；仅要求审阅时在聊天里给出建议，不写回。未获授权的匹配项列为待复查，不顺手批量改写。
